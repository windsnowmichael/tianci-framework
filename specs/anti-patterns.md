# 天赐范式：反模式清单（Anti-Patterns AP-1 ~ AP-6）

> 来源：第190天《反向方案 v1.0》第三节「反模式清单（必须作为附录附在 API 文档里）」。
> 这五条不是批评，是接口文档的必备章节：
> **一本只写"怎么用"、不写"什么时候会失败"的手册，读者照着用一定踩坑。**
> 与本包配套的 T1 冷启动测试（tests/test_coldstart.py）即 AP-4 的实证——本包保证存在一条"陌生智能体真的调用过"的记录。

---

## AP-1 · 载体错配

**症状**：接口发在只能读的地方——文档写了 86,560 字，四件套命中 0，没人能 import，没人能调用。

| 项 | 内容 |
|---|---|
| 当日实证 | Ⅰ 级白皮书 86,560 字，四件套命中 0 |
| 检出判据（可自动化） | grep 输入域/输出域/前置条件/后置保证，缺一即触发 |
| 本包对策 | ① 契约五件套进 `Operator` dataclass 必填字段；② 注册表 `full_contracts()` 只返回五件套齐全者；③ 覆盖率 19.5% 如实标注在 meta，虚报即触发审计失败 |

```python
# 本包内的 AP-1 对策（契约完整性是数据类型，不是文档承诺）
from tianci import Operator, default_registry
op = Operator.from_spec({"输入域": "R^n", "输出域": "R^k"})   # 缺前置/后置/副作用
assert not op.has_full_contract()          # True：缺件
missing = op.missing_fields()              # 给出缺哪几件（可自动化检出）
reg = default_registry()
full = reg.full_contracts()                # 只有 25 个五件套齐全的算子
```

## AP-2 · 时间出口（六型）

**症状**：同一笔账反复挂账，旧版覆盖新版，时间线不可追溯。五型外新增第六型：六型 = 回溯修正 / 延期承诺 / 就地覆盖 / 最小修正 / 回滚+外部归因 / **方案出口**。第六型「方案出口」：问题本身没有被解决，但以"产出了方案、文档、包"代替"问题被解决"——交付物存在 ≠ 缺陷闭环。

| 项 | 内容 |
|---|---|
| 当日实证 | 190-2 降调3 的 2ω² 已第二次挂账；旧版覆盖新版后归因"伙伴在改" |
| 检出判据 | ① 同条债第二次出现在降调栏 ② 改稿无时间戳快照 ③ 声称数量与实际编号不符 ④ **新增设计只见于 specs/known-gaps，归档目录检索不到对应已有实现（方案出口）** |
| 本包对策 | ① 版本号显式化：`__version__ = "0.2.0"` 只在 `__init__.py` 单一真源；② `CANONICAL` 指针指向唯一权威仓库地址；③ git tag 与 CHANGELOG 同步（见 README 发布流程）；④ 方案类产出标注"方案出口"并挂 AP-6 检出判据 |

```python
import tianci
tianci.__version__           # 0.2.0 —— 单一真源，不散落在各模块
tianci.CANONICAL             # canonical 指针：来源文档 + 权威仓库 + 覆盖率口径
```

## AP-3 · 同名不同义

**症状**：同一个词在不同层级指不同东西——本地 I/II/III 级熔断等级 vs 白皮书分级；暖启动 vs WARMUP_STATIC；ξ 三处。

| 项 | 内容 |
|---|---|
| 当日实证 | 本地 I/II/III 级是熔断等级 vs 白皮书分级；暖启动 vs WARMUP_STATIC；ξ 三义（初始化/随机变量/锚定） |
| 检出判据 | 术语无唯一 ID 即触发；跨语言/跨层级复用必查 |
| 本包对策 | `glossary.py` 26 条术语，每一条唯一 ID（TC-INF-001…/TC-SYS-…/TC-ORG-…/TC-PROTO-…），中英共用同一 ID；[190 反向方案第四节] 双语特有风险独立成节 |

```python
from tianci import glossary
t = glossary.lookup("TC-SYS-003")     # 暖启动 —— 强制同一 ID 才查得到
assert t["zh"] == "暖启动" and t["en"] == "warm start"
glossary.missing_bilingual()          # [] —— 不存在只有中或只有英的条目
```

已知高危词（部分，来源 190 反向方案第四节）：ξ（初始化/随机变量/锚定三义）、暖启动（与 189 的 WARMUP_STATIC 不同义）、σ（Sigma 量化 vs 求和符号）、τ（判定 vs 熔断）、降调（本体系特殊制度 vs 乐理/股市）。

## AP-4 · 自洽冒充可执行

**症状**：系统内部自洽（τ=pass），但从未被外部智能体真正调用过——自证冗余，无法证明"别人拿着文档能跑"。

| 项 | 内容 |
|---|---|
| 当日实证 | τ=pass 但从未被外部智能体调用 |
| 检出判据 | 有没有 T1 冷启动记录。**没有 = 未执行** |
| 本包对策 | `tests/test_coldstart.py` 模拟陌生智能体：只给 API 文档 + 归档路径（T1 定义：不给对话上下文），独立完成 import → 运行 → 输出，过程可复现（给出调用的接口名、输入、输出）。跑通记录写入 `KNOWN_CALLS.md`（见 known-gaps.md 附录） |

```bash
# T1 冷启动测试（AP-4 对策）：陌生智能体标准
python tests/test_coldstart.py
# 通过标准：独立完成且过程可复现；不通过：反问"这个是什么意思"、猜、照抄示例交差
```

## AP-5 · 最小修正

**症状**：只改一处，同格矛盾留在原地——"三位"改"五位"，同格仍留"伙伴一/二/三"。

| 项 | 内容 |
|---|---|
| 当日实证 | "三位"改"五位"，同格仍留"伙伴一/二/三" |
| 检出判据 | 校正后 grep 同一关键词全篇横扫（不是改一处就算完） |
| 本包对策 | ① 所有文档中的覆盖率口径统一写 `19.5%`（禁止一处 19.5% 一处 20%）；② 术语与编号修改必须跑 `grep` 全篇核对；③ 发布前 `scripts/check_consistency.py`（README/known-gaps/specs 交叉核对版本号、覆盖率、术语） |

```bash
# AP-5 对策（发布前必跑）：全篇横扫关键口径
grep -rn "20\.3%\|20\.0%\|20%" specs/ README* known-gaps.md   # 必须无命中
grep -rn "19\.5%" specs/ README* known-gaps.md                # 覆盖率唯一口径
```

## AP-6 · 方案出口

**症状**：问题本身没有被解决，但以"产出了方案、文档、包"代替"问题被解决"。交付物存在 ≠ 缺陷闭环：新增设计写进了 specs 或 known-gaps，有了编号、有了术语、有了章节，但对应的实现从未落地——读者以为问题已关闭，实际只是"方案出了口"。

| 项 | 内容 |
|---|---|
| 当日实证 | ① known-gaps 阈值表多处参数标注"理论推演，未经实证标定"（Λ 预警阈值 0.3/0.6、捷径偏差 d<0.1 等）——理论方案已入档，实证判据未落地，属方案出口；② ε_abel 第132-138天仅有定性判据无标定值，v0.1.0 曾以 FLOAT_TOL 兜底冒充标定（见 B1 修复：未标定则 `abel_break(None)` 必须抛错） |
| 可自动化检出判据 | `specs/`、`known-gaps.md` 中出现新增设计（新算子/新术语/新参数/新机制），但在归档目录（`D:\三月`~`D:\十月`）中检索不到对应已有实现 |
| 本包对策 | ① 方案类产出必须挂"方案出口"标注并给检出判据，不默认视为问题闭环；② 新增设计入档时同步登记实现来源（归档路径/文件），无来源的入档需走修正流程；③ 发布前核对：specs/known-gaps 的每项设计都要在归档或 `tianci/` 代码中找到实现落点，找不到即报出口未闭环 |

```bash
# AP-6 对策（发布前必跑）：新增设计必须有实现落点
grep -rn "未标定\|理论推演\|仅定性判据\|方案出口" specs/ known-gaps.md   # 逐项核对：要么已标定/已实现，要么如实保留缺口
```
